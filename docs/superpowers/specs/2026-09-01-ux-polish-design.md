# 子项目 E · UX 收尾设计

> 状态：已批准（2026-09-01）
> 范围：任务完成桌面通知、全局进度总览、失败任务智能诊断、待转换文件表多选批量操作
> 不做：预设管理 UI（roadmap 延后）、产物转存书库、移动端长听增强

## 1. 任务完成桌面通知

- 浏览器 Notification API；首次使用请求授权（拒绝则静默降级，按钮变灰说明）
- 触发条件：页面 `document.hidden === true` 且任务进入终态（done/failed）；失败通知带错误摘要
- 点击通知 → `focus()` 回页面
- 设置开关：`settings.notifications`（服务端持久化，依赖子项目 B）；默认关
- 入口：侧栏任务卡标题行小铃铛按钮

## 2. 全局进度总览

- 侧栏「任务」标题行右侧显示聚合状态：`8/12 完成 · 总体 67%`
- 计算：内存态任务（done 计 1；进行中按 progress 加权）；无任务时隐藏
- 有活动任务时浏览器标签页标题显示 `(67%) Audiobook Converter`（切走也能瞟一眼）

## 3. 失败任务智能诊断

- 任务卡片渲染时检查：status=failed 且 source_ids 引用的文件已不在注册表/书库 → 重试按钮禁用 + 提示「源文件已删除，可在已上传文件重新加入后再试」
- 源仍存在 → 重试按钮照常
- 不改 API，纯前端诊断（内存态已具备全部信息）

## 4. 待转换文件表多选批量操作

- 表头新增 checkbox（全选/半选态）；行首 checkbox 列（放在 # 序号列之前）
- 勾选 ≥1 时表格上方浮出操作条：「移除所选」「全不选」「已选 N 个」
- 批量移除 = 现有单文件删除逻辑循环（含 cover 清理、会话保存）
- 与拖拽排序共存：checkbox 列 `nosort`；拖拽仍按行
- a11y：checkbox aria-label「选择 {文件名}」，全选 aria-label
- 操作条样式复用「已上传文件」tab 现有批量操作条

## 5. 测试

**单元**：
- 全局进度计算（混合 done/running/queued）
- 诊断判定（源存在/不存在 × failed 状态）

**E2E**：
- 通知开关持久化（改设置 → 重启 → 保持）
- 勾选 3 文件 → 批量移除 → 列表计数与 file-empty 状态
- 全局进度文本随任务完成更新
- 失败任务（删源后重试）按钮禁用 + 提示可见
